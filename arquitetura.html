✦ S3 Files — O que mudou

  • • Antes: s3.getObject(Key) + cache em /tmp + lógica de hit/miss
  • • Depois: fs.readFileSync('/mnt/templates/pdf/{id}.hbs')
  • • Antes: S3 multipart upload manual com SDK
  • • Depois: fs.writeFileSync('/mnt/outputs/{path}', buf)
  • • Arquivo escrito no mount aparece no S3 imediatamente — presigned URL gerada depois
  • • TemplateLoaderService eliminado — zero lógica de cache customizada

Requisitos S3 Files em Lambda

  • • Lambda deve estar em VPC com subnet que tenha mount target
  • • Security Group: Lambda ENI → porta 2049 (NFS) → mount target SG
  • • IAM execution role: s3files:ClientMount
  • • CDK: fn.addFileSystem(s3fs.FileSystem.fromBucket(...))
  • • Access Point auto-criado se não existir (UID/GID 1000, path /lambda)

Concorrência no mount compartilhado

  • • Múltiplas invocações Lambda leem /mnt/templates simultaneamente — sem lock
  • • Template Store é read-only no mount → zero conflito de escrita
  • • Output mount: cada worker escreve em path único {hash}.{ext} — sem colisão
  • • EFS/S3 Files garante consistência — arquivo visível no S3 após o write fechar
  • • Ideal para o caso de múltiplos workers PDF em paralelo com o mesmo template

Custo S3 Files vs antes

  • • S3 Files usa EFS internamente — custo: ~$0.08/GB-mês (EFS Standard)
  • • Templates store raramente passa de poucos MB — custo negligenciável
  • • Elimina egress de S3 SDK para downloads repetidos de template
  • • Output via mount: sem custo de PUT adicional além do armazenamento S3
  • • Savings superam o custo do NFS Interface Endpoint se volume de jobs for alto

Template update — fluxo de deploy

  • • Designer edita template local e faz aws s3 cp template.hbs s3://bucket/templates/pdf/id/v2.hbs
  • • Arquivo aparece no mount de todos os workers em segundos
  • • Template Registry DynamoDB atualizado: version: 'v2'
  • • Próximos jobs usam v2 automaticamente — sem redeploy de Lambda
  • • Rollback: atualizar Registry para version: 'v1'

Mail template via mount

  • • Mail templates também ficam em /mnt/templates/mail/{id}/{locale}.hbs
  • • Worker lê, Handlebars renderiza, SES envia como Raw — tudo na mesma invocação
  • • Suporte a i18n: pt-BR.hbs, en-US.hbs no mesmo FS
  • • SES Native Templates ainda disponível para casos simples (variáveis básicas)
  • • mailTemplateId no Template Registry aponta para o subpath correto
